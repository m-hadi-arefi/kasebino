# Plan — ADR-081 QR Acquisition Architecture Decision

## Summary

Encode MerchantOS **QR acquisition** at `src/qr-acquisition/`: stable storefront canonical URL with `?src=qr` as QR payload (via `buildStorefrontPath`), MinIO `qr` bucket asset ref, Persian sticker/print notes for Iranian storefronts, and attribution event contract (`StoreQrGenerated` / `StorefrontVisited`+`source=qr` / `MembershipCreated`+`source=qr`). No merchant print UI page this cycle (uiuxpromax N/A → ARD-033 remainder / merchant dashboard).

- Jalali: N/A this cycle (no date widgets on QR artifacts)

- Checklist (QR contract + sticker/landing copy):

## Database design

- `src/qr-acquisition/` — Decision + helpers:
  - `buildQrTargetUrl(storeSlug, opts?)` → `/s/{slug}?src=qr` (+ optional campaign id for future)

  - MinIO: `StoreQrRef` VO / object-key helper on `qr` bucket
  - Events reserved: `StoreQrGenerated`, `StorefrontVisited` (`source=qr`), `MembershipCreated` (`source=qr`)

  - Security: forbid secrets/tokens/PII in QR payload
  - Store must be `active` for public scan attribution note
  - API paths reserved: `GET/POST /api/v1/stores/:id/qr[+regenerate]`
- Align with `STOREFRONT_URL_POLICY.qrSourceQuery` / membership source `qr` (ADR-007)
