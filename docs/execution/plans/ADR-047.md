# Plan — ADR-047 Data Integrity Soft Delete and Audit Fields

## Summary

Encode MerchantOS data-integrity rules as an importable contract in `src/data-integrity/`: soft delete via `deleted_at`; mandatory `created_at`/`updated_at` (UTC `timestamptz`); optional `created_by`; optimistic `version` where concurrent writers; partial uniques `WHERE deleted_at IS NULL`; forbid hard-delete of auditable business data / memberships without explicit retention policy; audit trail via `AuditPort` shape deferred to Mongo `mos_audit` (ADR-058). Assert helpers + Vitest. Contract-only — no concrete domain tables or Mongo adapters.

## Iranian First impact

- Persian text: soft-delete / audit payloads must preserve UTF-8 `fa` product/customer content; no ASCII scrubbing of audited summaries
- RTL: N/A at SQL/integrity layer (presentation remains RTL)
- Jalali: timestamps store UTC; display → Asia/Tehran + Jalali in presentation
- تومان: money integrity unchanged (integer IRR minor units); audit summaries must not reformat money into ambiguous floats
- Iranian workflows: CRM restore stories (soft delete); memberships never hard-deleted without policy (store-first)

- Checklist: UX N/A (contract-only); Persian content preservation encoded on audit + soft-delete rules

## Database design

- No new concrete domain tables in this ADR (schema remains empty until domain ADRs)
- Column standards (all applicable OLTP tables):
  - `created_at` / `updated_at` `timestamptz NOT NULL` (UTC)
  - `deleted_at` `timestamptz NULL` when soft-delete applies (customer-visible / auditable / membership)
  - Optional `created_by` UUID (actor) when attribution required
  - `version INT NOT NULL DEFAULT 1` when concurrent writers
- Partial unique indexes include `WHERE deleted_at IS NULL` (align ADR-044)
- Hard delete forbidden for auditable entities and `store_memberships` without retention/purge policy ADR
- Purge jobs / physical delete → future retention ADR
- Audit: define `AuditPort` contract now; Mongo insert-only implementation → ADR-058; optional thin PG `audit_logs` noted
