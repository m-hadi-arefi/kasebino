# Plan — ADR-045 Query Design Standards

## Summary

Encode MerchantOS OLTP query design standards as an importable contract in `src/query-design-standards/`: always filter `merchant_id` (tenant) and never trust client-only tenant claims; prefer keyset pagination over deep OFFSET; select projections (no `SELECT *`); avoid N+1 via batch/`inArray`/join; repositories only for OLTP access; soft-delete exclusion on default reads; no cross-module domain joins (compose in application / events); separate read vs write paths with CompleteSale as single-TX write exemplar; prefer Redis before PG for hot entities / dashboard projections (no unbounded aggregates on request). Assert helpers + Vitest. Contract-only — no concrete repository/query implementations.

## Database design

- No new concrete domain tables or Drizzle query code
- Standards for every future list/read/write path:
  - `WHERE merchant_id = $1` (+ JWT claim match) on tenant queries
  - `AND deleted_at IS NULL` when soft-delete applies (default reads)
  - Keyset pagination for hot/large lists; OFFSET only for small admin pages
  - Explicit column projections — no `SELECT *`
  - Batch loads / joins — no N+1 loops
  - Repositories only; no Drizzle in domain/UI/route handlers
  - Application composition across modules — no domain cross-module SQL joins
  - Dashboard KPIs via projections + short Redis TTL, not unbounded `SUM` on request
- Align with `docs/architecture/query-strategy.md`, ADR-043 soft-delete/tenant, ADR-044 indexing, ADR-004 modular monolith
