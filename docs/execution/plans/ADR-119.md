# Plan — ADR-119 Security Hardening Runtime

## Summary

Enforce runtime security for NFR-04: Helmet-equivalent headers, strict CORS, CSRF on cookie-session mutations, keep realtime identity session-only (no `x-merchant-id`), staging OTP non-leak regression, and a checked-in pen-smoke checklist with last-run evidence. DLQ/max-retry remains owned by ADR-109 (coordinate only).

## Decision being implemented

- FR-1: Security headers on HTML/API responses (middleware + `next.config` headers)
- FR-2: CORS locked to `CORS_ALLOWED_ORIGINS` (+ localhost defaults)
- FR-3: CSRF double-submit token required for cookie-session mutating API routes
- FR-4: Realtime token rejects header-only identity (session JWT only; regression test)
- FR-5: Staging OTP responses never include `devOtp` (regression tests)
- FR-6: Pen-smoke checklist + last-run results section checked in

## Task breakdown

1. Write this plan (`docs/execution/plans/ADR-119.md`) — **before code**.
2. Add `src/infrastructure/security/` runtime module:
   - Header builders (CSP, HSTS staging/prod, XCTO, XFO, Referrer-Policy, Permissions-Policy, COOP)
   - CORS allowlist resolve + apply / preflight
   - CSRF issue/validate (double-submit cookie + `x-csrf-token`)
   - Persian `SECURITY_RUNTIME_MESSAGES_FA`
3. Wire middleware: apply headers on all matched responses; CORS for `/api/*`; CSRF gate for mutating cookie-session `/api/v1/*` (exempt webhooks + Auth.js).
4. `next.config.ts` `headers()` for static/default responses (defense in depth).
5. Client helper to attach CSRF token on same-origin fetches (for POS/dashboard later).
6. Realtime: regression that `x-merchant-id` alone never authorizes; never read that header in authorizer path.
7. OTP: confirm/strengthen `shouldReturnDevOtp` + HTTP tests for staging/production; console SMS local-only (reuse factory).
8. `docs/security/pen-smoke-checklist.md` with pass/fail + last-run evidence.
9. Flip `SECURITY_HEADERS_CHECKLIST.runtimeWiring` / CORS runtime markers from deferred → wired (ADR-119).
10. Env: document `CORS_ALLOWED_ORIGINS` in `.env.example`.
11. Run `npm run validate`.

## Risks

- CSP too strict → Next inline styles/scripts break — start with Next-compatible CSP (`'unsafe-inline'` styles; tighten with nonces later)
- CSRF breaks handler unit tests if applied inside handlers — **middleware-only** so pure handler tests stay green
- Preview deploy origins — `CORS_ALLOWED_ORIGINS` allowlist required
- DLQ gap remains until ADR-109 (explicit non-goal ownership)
