## uiuxpromax gate (ADR-021) — BEFORE UI code

**Evidence:** `.cursor/skills/uiuxpromax-integration/SKILL.md` + `docs/uiux/*` present; external binary N/A → skill/docs fallback.

### Brief (fa-IR / RTL / ~390px Android)

- **Persona:** صاحب مغازهٔ تازه در کرمان — بعد از ورود با پیامک، می‌خواهد نام کسب‌وکار، آدرس مغازه، رنگ/لوگو و لینک ویترین را آماده کند، بعد صندوق.
- **Context terms:** کسب‌وکار، مغازه، آدرس، نقشه، برند، لوگو، ویترین، QR، فروشگاه فعال، راهاندازی
- **Composition:** One-column wizard (`/onboarding`); step progress text (not card collage); brand/trade name prominent; daylight DS tokens; no purple/cream clichés; no hero overlays.
- **Screens:**
  1. **کسب‌وکار** — نام تجاری + اسلاگ لاتین ویترین‌محور؛ خطای تکراری اسلاگ فارسی
  2. **فروشگاه اول** — نام نمایشی + اسلاگ فروشگاه + آدرس ایرانی + lat/lng (reuse ADR-104 patterns)
  3. **برندینگ** — رنگ اصلی (hex در محدوده DS) + بارگذاری لوگو (ADR-111) یا رد موقت
  4. **ویترین و QR** — نمایش `/s/{slug}` + CTA چاپ QR + چک‌لیست فعال‌سازی (فروشگاه آماده / محصولات / اولین فروش با موبایل)
  5. **مدیریت فروشگاه‌ها** (`/stores`) — لیست، سوییچر فروشگاه فعال، ایجاد فروشگاه دوم
- **States (Persian):** loading «در حال بارگذاری…» / resume mid-wizard / SLUG_TAKEN / geo نامعتبر / network / empty stores
- **Component map:** `OnboardingWizardClient`; `StoreSwitcher`; extend `src/modules/store/ui` + new `src/modules/merchant/ui` onboarding copy/API; `assertUiuxGate` in module tests
- **A11y:** labeled steps; `aria-live` errors; ≥44px; focus order RTL-natural

### Visual direction

Utility retail daylight; stepped form with clear primary CTA; store switcher as compact select/sheet in merchant chrome — not a dashboard of stats.

## Tasks

1. **Plan + uiuxpromax brief** (this file) — before code
2. **Persistence:** `MerchantRepository.findByOwnerUserId` (Drizzle + in-memory); one-owner constraint on create
3. **AUTH-06 claims:** lazy resolve `merchantId` + `merchant_owner` roles from owner when JWT still null; `resolveClaims` on OTP verify; optional session refresh path
4. **Active store:** httpOnly cookie `mos-active-store-id` + `GET/PUT /api/v1/stores/active`; helper used by UI clients; POS prefers cookie over local-only first store
5. **Onboarding API:** `GET /api/v1/merchants/me/onboarding` checklist; create merchant/store branding already wired — ensure activate merchant+store on wizard complete when geo present
6. **UI:** `/onboarding` wizard (resume); store create `/stores/new`; enhance `/stores` + `StoreSwitcher` on dashboard/POS; redirect incomplete merchants from `/dashboard` → `/onboarding`
7. **Slug policy:** document **immutable after first publish** (storefront live); create-time uniqueness only; no rename UX
8. **Tests + validate** with `DATABASE_URL=postgres://merchantos:merchantos@localhost:5433/merchantos`
9. **STATUS / progress-log** notes; **do not** move ADR to `done/`
