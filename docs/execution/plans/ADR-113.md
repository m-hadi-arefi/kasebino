# Plan — ADR-113 RBAC Authorization Enforcement at Routes and Use Cases

## Summary

Wire mandatory AuthZ on `/api/v1` merchant/admin handlers using JWT/session-derived `AuthContext` and `requirePermission()` / `authorize()`. Deny by default; never trust body `merchantId` alone. Expand checks beyond admin module; keep Persian 401/403 messages; audit admin suspend.

## Decision being implemented

FR-1 deny-by-default; FR-2 `requirePermission` at handler/application boundary; FR-3 store scope via existing `authorize()`; FR-4 negative tests; FR-5 admin actions audited (already in admin use cases — assert via HTTP test).

## Task breakdown

1. Add `requirePermission()` (alias over `authorize` / `assertPermission`) in `src/rbac` + re-export from identity authorization.
2. HTTP bridge in `require-auth.ts`:
   - `requireMerchantPermission(session, correlationId, { permission, bodyMerchantId?, resourceStoreId? })`
   - Combines session auth + tenant resolve from JWT + `authorize()`; maps `AuthorizationError` → Persian fail envelope
   - `requireAdminPermission` wraps platform_admin + `admin.platform`
3. Map AuthZ codes in `domain-error.ts` (`UNAUTHENTICATED`→401; `FORBIDDEN`/`CROSS_TENANT`/`STORE_SCOPE_DENIED`/`CUSTOMER_STAFF_BOUNDARY`→403).
4. Replace bare `requireMerchantAuth` on protected merchant handlers with permission-gated helper; keep session merchantId as resource scope (ignore body alone).
5. Tighten clear cross-tenant reads (e.g. CRM list by storeId must verify store belongs to session merchant).
6. Tests (acceptance):
   - Unauthenticated merchant API → 401 + Persian message
   - Cross-tenant (body merchant mismatch / wrong merchant resource) → 403
   - Non-admin cannot suspend → 403
   - Admin suspend writes audit event (search AuditStore)
   - Wrong role (store_employee without permission) denied where applicable
7. Export helpers from `src/infrastructure/http/index.ts`.
8. Run `npm run validate`.
