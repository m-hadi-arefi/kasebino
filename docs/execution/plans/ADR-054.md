# Plan — ADR-054 Cache Invalidation via Domain Events

Ship **event → key delete maps** and `invalidateOnEvent` in `src/cache-invalidation/`: mutations emit domain events; CacheInvalidationService deletes Redis (or in-memory port) keys using ADR-053 builders; next cache-aside read rebuilds from PostgreSQL. ### Event → key map (MVP)

| Event | Keys deleted (when IDs present) |
| --- | --- |
| `StoreUpdated` | `store:{storeId}`; storefront product/info-class siblings when storeId known (`sf` info via store id segment optional); no SCAN |
| `ProductUpdated` | `product:{productId}`; `sf:product:{productId}`; `barcode:{barcode}` if provided |
| `SaleCompleted` | `analytics:overview`; `wallet`/`membership` when storeId+customerId; `stock:{storeId}:{productId}` + `sf:product:{productId}` per `lineProductIds` |

Prefer explicit ID-based deletes; hashed list/catalog keys remain opt-in registry (cache-strategy playbook) — out of MVP unless `pageHash` supplied.
