# Plan — ADR-071 Scalability Stateless Multi-Instance

## Summary

Encode **NFR-02** as an importable architecture contract in `src/scalability-stateless/`: MerchantOS app nodes are **stateless**; auth uses **JWT** (no sticky sessions / no server session store); shared **Redis / PostgreSQL / MongoDB / EMQX** back the data and coordination planes; production scales **horizontally behind a load balancer** with **N ≥ 2** instances and **no sticky affinity required**.

This ADR does **not** implement k8s manifests or LB config (ADR-070 / ADR-072). It makes the scalability decision **testable and enforceable** by asserting against existing ADR-004 / ADR-033 / ADR-051 contracts and auth/runtime wiring.

## Forbidden production sticky / local state (contract)

| Pattern | Production | Allowed |
| --- | --- | --- |
| LB sticky session affinity | Forbidden (not required) | N/A |
| Database / server session store | Forbidden | JWT (ADR-033) |
| In-process-only rate limit as sole production path | Forbidden | Shared Redis (ADR-051/055/108) |
| In-process-only cache as sole production business cache | Forbidden | Shared Redis cache-aside |
| Local disk session / upload SoT on app node | Forbidden | MinIO / shared stores |
| `globalThis` connection pools for PG/Redis drivers | Allowed (per-process pools; not request sticky identity) | Documented HMR/pool caveat |
