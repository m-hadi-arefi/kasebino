# Plan — ADR-043 Database Modeling Standards

## Summary

Encode MerchantOS OLTP modeling standards as an importable contract in `src/database-modeling/`: query-first table design rules (snake_case plural tables, UUID PKs, UTC `timestamptz` audit columns, optional soft-delete `deleted_at`, `merchant_id` on tenant tables, Persian UTF-8 text, IRR money as integer minor units, optimistic `version` when concurrent, no cross-module domain joins per ADR-004). Assert helpers + Vitest. Contract-only — no domain tables (ADR-044+ indexes / domain ADRs own concrete schema).

## Iranian First impact

- Persian text: UTF-8 `text`/`varchar` columns required; ASCII-only collations forbidden
- RTL: N/A at SQL layer (presentation remains RTL)
- Jalali: timestamps stored UTC `timestamptz`; Jalali + Asia/Tehran at presentation
- تومان: money columns are integer minor units IRR; display تومان stays presentation/`Money` VO
- Iranian workflows: tenant `merchant_id` models Iranian merchants/stores; barcode+name search deferred ADR-044/050
- Mobile: query budgets / indexing deferred ADR-044–045; modeling protects correct types
- Checklist: UX N/A (infra/contract-only); UTF-8 Persian + integer money encoded

## Database design

- No new concrete domain tables (schema index stays empty export)
- Standards documented for every future PG ARD Database Design section:
  - Naming: `snake_case` plural tables; `snake_case` columns
  - PK: UUID (`id`)
  - Audit: `created_at`, `updated_at` `timestamptz` UTC NOT NULL
  - Soft delete: optional `deleted_at` `timestamptz` NULL; partial uniques when used
  - Tenant: `merchant_id` UUID required on tenant-owned tables
  - Money: integer minor units IRR (not float/`numeric` for OLTP money)
  - Optimistic lock: `version` INT where concurrent writers
  - FKs / checks / growth estimates mandatory in ARDs (guidelines)
- Align with ADR-041 `UNIVERSAL_COLUMN_EXPECTATIONS` / tenant isolation; ADR-042 Persian text column types
