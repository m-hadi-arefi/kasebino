## Ready policy (fail-closed critical)

| Check | Default | Failure → HTTP |
| --- | --- | --- |
| **postgres** | **required** | 503 `not_ready` |
| **redis** | **required** (auth OTP fail-closed / cache paths critical) | 503 `not_ready` |
| **mongodb** | checked when `MONGODB_URL` set; **optional** unless `MOS_READY_REQUIRE_MONGO=1` | optional down → still 200 (reported); required down → 503 |
| **emqx** | checked when `MQTT_URL` set; **optional** unless `MOS_READY_REQUIRE_EMQX=1` | same |
| **minio** | checked when `MINIO_ENDPOINT` set; **optional** unless `MOS_READY_REQUIRE_MINIO=1` | same |

Rationale: OLTP + Redis are request-serving critical. Mongo analytics, EMQX realtime, and MinIO receipts already have app-level degradation / retry (ADR-110/109/111). Overly strict optional checks risk LB flaps (ADR Risk).

## Response shape

```json
{
  "status": "ready",
  "checks": {
    "postgres": { "ok": true, "required": true, "latencyMs": 4 },
    "redis": { "ok": true, "required": true, "latencyMs": 2 },
    "mongodb": { "ok": true, "required": false, "latencyMs": 8 },
    "emqx": { "ok": false, "required": false, "latencyMs": 50, "detail": "unreachable" },
    "minio": { "ok": true, "required": false, "latencyMs": 12 }
  }
}
```

- `detail` is safe enum-ish (`unreachable` | `missing_config` | `timeout`) — never URLs/credentials.
- Skipped optional when URL unset: `{ ok: true, required: false, skipped: true }`.

## Timeout budget

- Per-check default **1500ms**; overall race **3000ms**.
- Checks run **in parallel**.
