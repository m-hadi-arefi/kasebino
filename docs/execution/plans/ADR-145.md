## 1. Executive Summary

ADR-145 closes two retention gaps in MerchantOS:
1. **Online Earn:** While POS sales earn points inline, `earnPointsForOrder` for online pickup orders is implemented but currently un-wired. Online order payments (`OrderPaid`) must automatically, idempotently credit customer store membership wallets with earned points.
2. **Coupons Cleanup:** The `coupons` table is an unreferenced orphan schema stub. Per ADR-145 decision, coupons are deferred, and the orphan table/schema is safely dropped to eliminate schema drift and keep the database surface clean.

## 3. Scope & Architecture Changes

### A. Loyalty Domain & Persistence
- **Idempotency Port:** Extend `PointsLedgerRepository` interface with `findEarnByOrderId(orderId: string): Promise<PointsLedgerEntry | null>`.
- **In-Memory & Drizzle Adapters:** Implement `findEarnByOrderId` in `InMemoryPointsLedgerRepository` and `DrizzlePointsLedgerRepository`.
- **`earnPointsForOrder` Idempotency:** Update `earnPointsForOrder` in `src/modules/loyalty/application/use-cases.ts` to query `findEarnByOrderId(input.orderId)` before crediting wallet, returning `{ wallet, points: 0, created: false, event: null }` if points were already earned for the order.

### B. Ordering & Event Wiring
- **`OrderPaid` Event Payload:** Update `orderPaidEvent` in `src/modules/ordering/domain/events.ts` to include `membershipId` and `customerId` when present on the `Order` aggregate.
- **`markPaid` Integration:** Pass `membershipId` and `customerId` when instantiating `orderPaidEvent` inside `ordering.markPaid`.
- **Outbox / Application Wiring:** Wire an `OrderPaid` event subscriber / outbox handler that invokes `loyalty.earnPointsForOrder` when an order with a valid `membershipId` is paid.

### C. Schema Cleanup (Coupons Drop)
- **Drizzle Schema:** Remove `coupons` table definition from `src/infrastructure/database/schema/loyalty.ts` and `src/infrastructure/database/schema/index.ts`.
- **Drizzle Migration:** Generate a clean migration SQL (e.g. `0007_drop_coupons.sql`) dropping `coupons` table and unique/index constraints (`coupons_merchant_id_code_uq`, `coupons_merchant_id_store_id_idx`).
- **Test Expectations:** Update Drizzle schema tests in `src/drizzle-orm-strategy/index.test.ts` to remove expectations for `coupons`.

## 6. Risks & Mitigation

| Risk | Mitigation |
| --- | --- |
| Double credit on webhook retry / outbox redelivery | Strict `findEarnByOrderId` check in application layer + database level idempotency. |
| Missing `membershipId` on guest orders | `earnPointsForOrder` cleanly skips when `membershipId` is null/empty without crashing the order payment flow. |
