## 1. Executive Summary

ADR-149 completes store working hours management for MerchantOS. While store domain models (`StoreHours`), JSON column persistence (`stores.hours_json`), and the `updateHours` domain use case exist, HTTP update routes (`PATCH /api/v1/stores/{id}`) and merchant UI forms currently do not expose operating hours. This task exposes `hours` in store HTTP endpoints, validates weekly schedules, and provides Persian RTL working hours display and management.

## 2. Iranian First UX & Localization Compliance

- **Iranian Week Structure:** Weekdays ordered starting Saturday (شنبه) to Friday (جمعه):
  - Saturday (`saturday` / `شنبه`)
  - Sunday (`sunday` / `یکشنبه`)
  - Monday (`monday` / `دوشنبه`)
  - Tuesday (`tuesday` / `سه‌شنبه`)
  - Wednesday (`wednesday` / `چهارشنبه`)
  - Thursday (`thursday` / `پنج‌شنبه`)
  - Friday (`friday` / `جمعه` — default weekend/closed day)
- **Persian Status Microcopy:** Store status labels (`باز است`, `بسته است`, `تعطیل`).
- **Time Format:** 24-hour time slots (`09:00` - `21:00`) with RTL alignment (`dir="rtl"`).

## 3. Scope & Technical Changes

### A. HTTP API & Schema Validation
- Extend store update Zod schema in `src/infrastructure/http/handlers/merchants-stores.ts`:
  - `hours`: object mapping day names (`saturday`…`friday`) to time slot arrays `Array<{ open: string; close: string }>` or closed flag `isClosed: boolean`.
- Wire `handleUpdateStore` in `src/infrastructure/http/handlers/merchants-stores.ts` to update store hours when `hours` payload is provided.
- Include `hours` object in `storeDto` and public storefront profile responses.

### B. Storefront & Merchant Integration
- Storefront profile DTO includes operating hours formatted for customer presentation.
- Merchant store management endpoints allow updating operating hours seamlessly alongside store address/branding.
