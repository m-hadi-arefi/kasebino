## 1. Executive Summary

ADR-148 provides full stock auditability for Iranian retail store operations. While `stock_movements` rows are recorded on inventory adjustments and POS sales, merchants currently only see current stock balance and last update timestamp. This plan introduces query capability by store and product, pagination via cursor, an HTTP API (`GET /api/v1/inventory/movements`), Persian reason mappings, and merchant UI history drawer components with Jalali date formatting.

## 2. Iranian First UX & Localization Compliance

- **Persian Reasons (`fa-IR`):** All inventory movement reason codes are translated to clear Persian shop-floor terms:
  - `pos_sale`: `فروش حضوری`
  - `online_order`: `سفارش آنلاین`
  - `manual_adjustment`: `اصلاح دستی انبار`
  - `initial_stock`: `موجودی اولیه`
  - `damage`: `ضایعات / خرابی`
  - `supplier_receive`: `ورودی از تامین‌کننده`
- **Jalali Timestamps:** Movement timestamps displayed in Jalali (Shamsi) calendar format using Tehran timezone (`Asia/Tehran`).
- **RTL Alignment:** Movement history tables, sheet drawers, and balance badges formatted in RTL (`dir="rtl"`).

- Add `listStockMovements` use case in `src/modules/inventory/application/use-cases.ts` supporting tenant scoping, `storeId`, optional `productId`, `limit` (default 20, max 100), and `cursor` (ISO string / ID).

### C. HTTP API
- Implement `handleListStockMovements` in `src/infrastructure/http/handlers/inventory.ts`:
  - Route: `GET /api/v1/inventory/movements?storeId={storeId}&productId={productId}&cursor={cursor}&limit={limit}`
  - Authz: `requireMerchantPermissionResolved` with `permission: "merchant.read"`.
  - DTO: returns `{ items: StockMovementDto[], nextCursor: string | null }`.

### D. Merchant UI
- Provide Persian movement history panel component / drawer for merchant inventory management (`app/(merchant)/inventory`).
