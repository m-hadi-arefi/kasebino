# Plan — ADR-032 Customer SMS OTP Authentication

## Summary

Encode passwordless **phone OTP** for **customers** (store members / storefront / PWA), fully separate from merchant staff OTP (`src/modules/identity` / ADR-031). Importable decisions contract in `src/customer-auth/` (audience isolation, `role=customer` JWT claims contract, distinct routes, AUTH-* / CUST patterns, explicit digital consent checkbox per ADR-091) plus `src/modules/customer-identity/` domain/application/infra — Iranian MSISDN, OTP challenges, `SmsPort` console/mock (ADR-083 Proposed), Persian auth errors + SMS templates. No NextAuth wiring (merchant ADR-033 remains merchant-scoped; customer session provider later), no Drizzle OLTP migration this cycle, no OTP UI screens (uiuxpromax N/A — screens deferred to ADR-023 / ARD-030 remainder).
