# Plan — ADR-041 PostgreSQL Architecture

## Summary

Encode PostgreSQL as the sole OLTP system of record for MerchantOS: UUID PKs, timestamptz audit columns, soft-delete expectation, row-level `merchant_id` isolation, UTF-8 Persian text, and connection via `DATABASE_URL` from compose / `.env.example`. Contract lives in `src/postgresql-architecture/`. No Drizzle client (ADR-042), no domain schemas (ADR-043+).

## Iranian First impact

- Persian text: UTF-8 encoding required for OLTP text columns (product names, notes, addresses); no ASCII-only collations/client encodings
- RTL: N/A at SQL layer (presentation remains RTL)
- Jalali / تومان: timestamps stored UTC (`timestamptz`); `Asia/Tehran` + Jalali conversion deferred to presentation; money integer minor units noted as OLTP expectation (detail ADR-043)
- Iranian workflows: tenant models Iranian merchants/stores via `merchant_id` (and later `store_id`) row isolation
- Mobile: connection pooling per instance protects POS latency budgets (pool sizing deferred with Drizzle client)
- Checklist: UX N/A (infra/contract-only); UTF-8 + UTC storage encoded in contract

## Database design

- Architecture contract only — no tables/migrations
- Universal column expectations documented at high level (detail in ADR-043 / ADR-047):
  - `id` UUID PK
  - `created_at` / `updated_at` timestamptz
  - `deleted_at` soft delete where applicable
  - `merchant_id` tenant discriminator (alias expectation: merchantId in app / merchant_id in SQL)
- Mongo must never be OLTP SoT (align ADR-056 / ADR-066 / PRODUCT_ARCHITECTURE)
- Connection: `DATABASE_URL` from `.env.example` / compose postgres service
- Engine: PostgreSQL latest stable (compose pins `postgres:16` as local parity — accepted stable channel)
