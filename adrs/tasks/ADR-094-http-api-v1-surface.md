## Title

Ship HTTP /api/v1 Route Handlers for MVP Domains

## Context

Only /api/health and /api/v1/realtime/token exist. Domain use cases are unreachable from clients.

## Problem

No merchant POS, CRM, catalog, loyalty, orders, payments, or admin can function end-to-end.

## Current State

app/api/v1/.gitkeep.md; API standards contracts in src/api-standards; no resource routes.

## Desired State

Versioned REST (or RPC-consistent) handlers for AUTH, POS, CRM, catalog, inventory, loyalty, storefront orders, payments webhooks, notifications list/read, admin merchants — all Zod-validated (ADR-030).

## Requirements

- Envelope errors RATE_LIMITED / UNAUTHORIZED / VALIDATION etc. per ADR-030
- Rate limiting wired for OTP/auth routes (ADR-055)
- Audience separation merchant vs customer vs admin
- Public storefront DTOs with ACL (ADR-077)
- OpenAPI or typed contract tests for critical routes

## Technical Design

Next.js App Router route handlers call application use cases. Composition root injects Drizzle repos + ports. No business logic in route files.

## Acceptance Criteria

- [ ] Merchant can call OTP, complete sale, list products via HTTP
- [ ] Customer can OTP, place pickup order via HTTP
- [ ] Admin can list/suspend merchants via HTTP
- [ ] Unauthenticated access rejected with correct envelope

## Risks

- Large surface area; must sequence by ARD critical path
- Leakage of internal IDs on public storefront
