## Title

Implement /api/ready Dependency Readiness Probe

## Context

/api/health liveness exists; readiness explicitly deferred.

## Problem

Orchestrators cannot know if Postgres/Redis are reachable before sending traffic.

## Current State

Health returns {status:ok}; Dockerfile HEALTHCHECK uses liveness only.

## Desired State

/api/ready checks DATABASE_URL + REDIS_URL (+ optional Mongo/EMQX) with short timeouts; used by deploy/LB.

## Requirements

- Fail closed on DB down
- Fast timeouts
- No auth required for probe
- Separate from liveness

## Technical Design

Route handler pings postgres SELECT 1 and Redis PING; return 503 with component statuses.

## Acceptance Criteria

- [ ] Ready 200 when Compose healthy
- [ ] Ready 503 if postgres stopped
- [ ] Health still 200 if redis down

## Risks

- Probe storms — keep lightweight
