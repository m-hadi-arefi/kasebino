## Title

Wire Redis Cache-Aside and Rate Limiting Runtime

## Context

Redis contracts and in-process rate limiter exist; redis client is URL-config stub only; no ioredis/node-redis dependency.

## Problem

PRD-mandatory cache-aside and OTP rate limits are not enforced in production middleware.

## Current State

src/redis-architecture + cache-aside + rate-limiting packages with memory backends for tests; infrastructure/redis/client.ts does not open connections.

## Desired State

Live Redis for cache-aside reads/invalidation and sliding-window rate limits on OTP/auth/admin routes.

## Requirements

- Default 10 rps
- Auth 5/min
- OTP 3/min
- TTLs 300/60/600 per PRD
- Event-driven invalidation

## Technical Design

Add redis client dependency; implement RedisCacheStore + RedisRateLimitPort; wire Next middleware / route wrappers; invalidate on domain events via outbox consumer.

## Acceptance Criteria

- [ ] OTP 4th request in a minute returns RATE_LIMITED
- [ ] Storefront catalog cache hits Redis
- [ ] Invalidation after ProductUpdated

## Risks

- Stale cache bugs
- Redis outage behavior must degrade safely
