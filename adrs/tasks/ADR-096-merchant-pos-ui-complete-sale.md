## Title

Production Merchant POS UI and CompleteSale Workflow

## Context

PRD POS-01..07 are P0. /pos is a Persian shell with offline status widgets only.

## Problem

Merchants cannot scan barcodes, capture phone, or complete sales.

## Current State

Domain CompleteSale use cases + offline contracts exist; UI has no cart/search/camera; no sale API.

## Desired State

Mobile-first Persian RTL POS: barcode/camera/fuzzy search, phone capture → membership, pay/complete <5s, receipt ref, SaleCompleted events.

## Requirements

- POS-01..07 acceptance criteria
- Barcode miss recovery UX (ADR-028)
- Toman display; Iranian phone keypad
- uiuxpromax brief before UI implementation
- Publish SaleCreated/SaleCompleted via outbox

## Technical Design

Compose staff PWA page with Zustand cart (ADR-025), TanStack Query product lookup (ADR-026), Zod phone schemas (ADR-027), CompleteSale use case over HTTP.

## Acceptance Criteria

- [ ] Barcode→add→phone→complete measured under 5s on mid Android
- [ ] Sale persists and awards loyalty points
- [ ] Receipt reference created (MinIO later ok if stub ReceiptRef)

## Risks

- Performance regressions without local catalog cache
- Offline P1 scope creep

## Dependencies

- ADR-094
- ADR-095
- ADR-050
- ADR-009

## Estimated Complexity

**XL**

## Iranian User Experience Requirements

- Persian copy + RTL for all new user-facing surfaces.
- Jalali dates and تومان formatting where money/time shown.
- Iranian phone (09xxxxxxxxx) validation for identity flows.
- Obey `docs/rules/iranian-first-development.md` and `docs/checklists/iranian-feature-checklist.md`.
