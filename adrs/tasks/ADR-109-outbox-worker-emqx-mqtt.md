## Title

Outbox Worker Process and Live EMQX Publishing

## Context

Transactional outbox schema + poller contracts exist; scheduled jobs return stub_acknowledged; EMQX client is URL stub; no mqtt.js dependency; no worker process.

## Problem

Domain events never leave the process; realtime and warehouse mirrors cannot work.

## Current State

outbox_events/processed_events schema stubs; src/outbox poller logic; emqx-realtime publish port; compose EMQX service up.

## Desired State

Long-running worker (Compose service) polls outbox, publishes to EMQX, marks processed; at-least-once with idempotency.

## Requirements

- Share transaction with OLTP writes
- Backoff/retry
- Metrics for lag
- Topic naming per ADR-037/038

## Technical Design

Add worker entrypoint (tsx/node). mqtt.js publisher adapter. Compose worker service depends_on postgres+emqx. DLQ policy documented.

## Acceptance Criteria

- [ ] Completing a sale appears on MQTT topic
- [ ] Worker crash resumes without loss
- [ ] Idempotent redelivery safe

## Risks

- Poison messages
- Duplicate consumer side effects
