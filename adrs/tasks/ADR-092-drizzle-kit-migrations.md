## Title

Generate and Apply Drizzle Kit OLTP Migrations

## Context

Schema TypeScript stubs exist under src/infrastructure/database/schema but migrations/ contains only .gitkeep. No OLTP tables can be created in PostgreSQL today.

## Problem

Without versioned SQL migrations, the product cannot persist any merchant, store, sale, order, or membership data.

## Current State

pgTable stubs (~22 tables) for merchants, stores, memberships, catalog, inventory, sales, loyalty, orders, payments, admin, outbox, notifications. **No `auth_users` / OTP challenge tables** despite identity/customer-identity modules. drizzle.config.ts points at schema. No generated SQL. README explicitly defers Kit generation.

## Desired State

Full forward-only Drizzle Kit migration set applied via npm run db:migrate in local Compose and documented as a pre-traffic deploy job — including identity OTP persistence tables required for merchant/customer auth.

## Requirements

- Add identity OLTP tables (merchant auth users, customer identity, OTP challenges) before/with baseline generate
- Generate baseline migration covering all existing schema modules + new identity tables
- UTF-8 / Persian-safe column types preserved
- Indexes for POS barcode, phone lookup, sale history per ADR-044
- CI reminder upgraded to fail if schema drifts without migration
- Document expand/contract rules for future breaking changes

## Technical Design

Run drizzle-kit generate against src/infrastructure/database/schema/index.ts. Review for locks/NOT NULL backfills. Apply with drizzle-kit migrate against Compose PostgreSQL. Keep migrations forward-only in production (ADR-046).

## Acceptance Criteria

- [ ] npm run db:generate produces committed SQL under migrations/
- [ ] Fresh Compose postgres + migrate yields all MVP tables
- [ ] Persian text insert/select round-trips without mojibake
- [ ] No Prisma/TypeORM or hand-authored baseline SQL

## Risks

- Large baseline migration if not reviewed for prod locks
- Schema stubs may need tightening before generate
