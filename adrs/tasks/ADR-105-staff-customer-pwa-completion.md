## Title

Complete Staff and Store Customer PWA Install Offline Sync

## Context

ADR-022/023/024 foundations + manifests exist; IDB e2e and sync HTTP missing; UI install prompts only.

## Problem

PWAs are not truly installable branded experiences with offline sale sync.

## Current State

staff-pwa + pos-offline + store-customer-pwa contracts; SW/IDB model documented; no service worker asset registered in next config proven.

## Desired State

Installable staff POS offline queue+sync; per-store customer PWA with branding; sync HTTP route with conflict policy.

## Requirements

- POS-08 P1 offline
- PWA installability
- Separate SW scopes staff vs store
- Never conflate PWAs

## Technical Design

Register SW via next-pwa or custom; IDB sale queue; POST /api/v1/pos/sync; store manifest per slug already patterned.

## Acceptance Criteria

- [ ] Staff install prompt works on Android Chrome
- [ ] Offline sale syncs when online
- [ ] Customer PWA installs with store name

## Risks

- SW caching stale storefront
- Sync dual-write races
