## Title

Pickup Order Lifecycle Merchant Board

## Context

Ordering domain models full pickup lifecycle; merchant has no orders board UI/API.

## Problem

Staff cannot advance Paid→Preparing→Ready→PickedUp→Completed.

## Current State

Order aggregate + timers + in-memory repo; pickup-only policy encoded; no routes.

## Desired State

Merchant real-time (MQTT or poll fallback) order board with Persian status labels and audited transitions.

## Requirements

- ORD-11 lifecycle
- Staff role authZ
- Realtime Order* events
- Cancellation/refund paths without delivery states

## Technical Design

Use ordering use cases over HTTP; subscribe via realtime-client; guard illegal transitions in domain.

## Acceptance Criteria

- [ ] All pickup states reachable via UI
- [ ] Illegal transition rejected
- [ ] Customer dashboard reflects status

## Risks

- Missed events if outbox worker down — need poll fallback

## Dependencies

- ADR-100
- ADR-109
- ADR-039
