## Title

Wire NextAuth/Auth.js App Router Handlers and Sessions

## Context

NextAuth config factory exists under identity infrastructure but no auth.ts / [...nextauth] handlers; next-auth is a dependency unused at runtime.

## Problem

No JWT session can be established for merchant or customer audiences; middleware only sets audience headers.

## Current State

createMerchantAuthConfig ready; NEXTAUTH_APP_ROUTER_WIRE_HINT documents future wire; middleware classifyRouteAudience only; AUTH_SECRET in .env.example.

## Desired State

Working Auth.js handlers for merchant + customer JWT sessions; secure cookies; tokenVersion claims; route protection for /dashboard /pos /admin /s/.../dashboard.

## Requirements

- Merchant JWT after OTP verify (AUTH-05)
- Customer JWT separate audience claims (ADR-032/033)
- Dev OTP returned **only** when explicitly allowed (prefer `NODE_ENV===development` or `MOS_RETURN_DEV_OTP=1`) — **not** for all non-production (current `shouldReturnDevOtp` would leak OTP in staging)
- Production and staging never return OTP in JSON (AUTH-03/04)
- Console SMS adapters must not be default outside local
- Replace x-merchant-id header bypass on realtime token
- CSRF/XSS cookie flags per ADR-033/076
- Extend CI lint/typecheck to cover `app/` (today ESLint ignores `app/**`; typecheck is contracts-only)

## Technical Design

Add auth.ts exporting handlers/auth/signIn/signOut from createMerchantAuthConfig + customer config. Protect routes via auth() in server components and middleware edge-compatible checks. Tighten `shouldReturnDevOtp` before any OTP HTTP route ships.

## Acceptance Criteria

- [ ] End-to-end merchant OTP → JWT → protected page
- [ ] End-to-end customer OTP → membership-scoped portal
- [ ] Production **and staging** responses never include OTP
- [ ] Realtime token rejects unauthenticated callers
- [ ] `app/` included in lint and (at least) Next build typechecking

## Risks

- Auth.js beta API churn
- Dual audience JWT confusion
